# Первое обучение Combustion Prediction Engine

Дата: 14 ноября 2026. Результат: **модель обучена, статус RESEARCH_ONLY**.

Актуальная сохранённая версия: `18a247279e5a25c26d6224be92febbfb01953970ccb81a41de20f01fbdf3d1c3`.
Текущая версия указана в `models/pmma_slab_co2_final/latest_research.json`.

## Что действительно реализовано

- Исполняемый `python -m ml.train`, режим аудита `--audit-only`.
- Извлечение данных из read-only SQLite и проверка соответствия исходному CSV и его SHA-256.
- Явный контракт физической серии, target, pre-burn features и совместимых источников.
- Отказы для seeds без источника, неизвестных протоколов, over-range/неточных targets,
  аномалий датчика, неполных критических признаков и неоднозначных чисел потока.
- Поиск дубликатов и связных групп по образцу или общему дню измерений/калибровки.
- Постоянные train/calibration/benchmark роли, обнаружение новых связей между ролями,
  защита frozen benchmark от исправления/удаления. Дополнения его групп не попадают в train.
- Масштабирование и категориальное кодирование обучаются внутри каждого CV fold.
- Полное переобучение на development data, а не на calibration/benchmark.
- Сравнение Linear Regression, Random Forest, Gaussian Process и небольшого MLP.
  Дополнительно — среднее training target и интерполяция без экстраполяции.
- Сохранение pipeline.joblib, JSON metadata, dataset snapshot с исходными строками,
  split manifest, метрик, исходных и CV/benchmark predictions, домена и причин запрета promotion.
- Сохранение предыдущих версий и сравнение с ними на том же независимом benchmark.
- Атомарный approved pointer только после всех gates; сейчас его нет.
- Интерфейс `ml.predict.assess(...)`, который не подменяет отсутствие одобренной модели
  числом из исследовательского кандидата.

Общая БД, исходные файлы NASA и backend коллеги не изменялись. Установлены только лёгкие
CPU-зависимости в существующее .venv; их версии закреплены в `requirements-ml.txt`.

## Задача и данные

Target: конечная концентрация CO₂ (% объёмных) в серии BASS-II с PMMA-пластинами и
встречным потоком. Это исследовательская задача по показаниям датчика в данном протоколе,
не прогноз скорости пламени и не оценка пожарной безопасности материала.

Известные до прогноза признаки: начальные O₂ и поток, толщина/ширина пластины, начальный CO₂,
признак повторного использования образца, описание одно-/двустороннего горения.
Не используются конечный O₂, минимум потока, outcome, скорость погасания или число кадров.

Из 20 CSV-прогонов этой серии пригодны для первого вычислительного эксперимента 19.
Один исключён: `<1` в исходном потоке нельзя считать точным значением 0,5 см/с.
Остальные 114 прогонов общей базы не относятся к выбранной физической серии.

| Роль | Прогоны | Независимые группы |
| --- | ---: | ---: |
| Development: fit и 4-fold grouped CV | 9 | 4 |
| Отдельная uncertainty calibration | 4 | 1 |
| Замороженный независимый benchmark | 6 | 2 |

Под «группой» здесь понимается консервативная связная группа по образцу/сессии.
Это не независимое внешнее NASA-исследование. Полная внешняя переносимость не проверена.

## Сравнение по development cross-validation

| Метод | MAE, п.п. CO₂ | Средняя MAE по группам |
| --- | ---: | ---: |
| Среднее training target | 0,3608 | 0,3615 |
| Linear Regression | 1,1299 | 0,7708 |
| Random Forest | 0,3882 | 0,3873 |
| Gaussian Process | 0,3926 | 0,3963 |
| MLP | 0,4938 | 0,4849 |
| Линейная интерполяция | Нет допустимых оценок | Нет допустимых оценок |

Random Forest — лучший **обучаемый** кандидат по заранее выбранной средней MAE групп.
Средний baseline оказался лучше него в development CV. Выбор кандидата не основывался
на результатах benchmark. Интерполяция отказалась на всех CV-точках: достаточного
геометрического покрытия для неё нет; значения за пределами покрытия не достраивались.

## Независимый benchmark

| Метрика | Random Forest | Средний baseline |
| --- | ---: | ---: |
| MAE, п.п. CO₂ | 0,3722 | 0,4206 |
| RMSE, п.п. CO₂ | 0,4419 | 0,4957 |
| R² | −1,8361 | −2,5686 |

Отрицательный R² означает, что различия значений в маленькой независимой выборке
объясняются плохо. Результат не становится надёжным из-за небольшого преимущества
над training-mean baseline на этих шести точках.

У calibration только одна независимая группа: конечный group-conformal interval для
заданного nominal 90% coverage не определён. Числовой интервал или «90% уверенности»
не выдаётся. Независимые точки также не проходят консервативную проверку поддерживаемой
области. Область применимости нельзя автоматически расширить по общим min/max.

## Повторный запуск

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ml.txt
.\.venv\Scripts\python.exe -m ml.train --audit-only
.\.venv\Scripts\python.exe -m ml.train
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

С теми же данными, task contract, manifest, кодом и окружением используется та же версия.
При новых совместимых данных создаётся новый immutable candidate; предыдущие версии
сохраняются. `approved.json` не обновится, пока не пройдены scientific/quality gates.
Один training process на task: stale `.training.lock` после аварийного завершения нужно
проверить по PID перед ручным удалением, а не игнорировать блокировку.

## Что ещё требуется

Это реализованный исследовательский этап для одной CO₂-задачи, не весь будущий predictor.
Для других физических targets нужны отдельные проверенные feature/target/source adapters.
Новые исследования без подтверждённой совместимости автоматически исключаются из training.
Нынешний importer с глобальным test_id по-прежнему требует согласованного исправления
перед массовым расширением источников; training-код не меняет этот backend.

Следующие научные работы: проверить режимы и время измерения CO₂, состояние/тип образцов,
собрать дополнительные независимые серии, задать допустимые ошибки в физических единицах
и независимо проверить uncertainty/domain. Предпочтительная будущая flame-spread модель
требует реально измеренных скоростей, которых в текущем CSV нет.

UI Predictor и Gemini-интерпретация численного прогноза пока не включены: сохранять
`INSUFFICIENT_DATA` корректнее, чем показывать неподтверждённые расчёты как рабочую модель.
