# Combustion Prediction Engine: аудит исходных данных

Дата: 14 ноября 2026. Ветка: `dev-ui`. Статус: анализ до реализации ML и обучения.

Новый запрос разрешает небольшие собственные ML-модели и тем самым расширяет прежнее
исключение в `Context.md`. Сам `Context.md` и файлы backend на этом этапе не изменялись.
Цель этого документа — определить реальную обучающую выборку, а не подтвердить заранее
выбранную модель. Ни один показатель ниже не является метрикой качества предсказания.

При прогнозе до горения запрещённые признаки: конечные O₂/CO/CO₂, достигнутый минимум

Даже полный airflow sequence может содержать реакцию оператора на исход эксперимента.
Начальные CO/CO₂ допустимы только для задачи, где их реально измерят до прогноза.

После исключения прогонов с существующими предупреждениями и требования условно

времён измерения, размеров камеры и источников ещё не подтверждена.

**Число кандидатов для аудита не равно числу допущенных обучающих примеров. Сейчас нет
ни одной серии с завершённым ML scientific review и независимой оценкой пригодности.**

## 6. Конкретные проблемы достоверности

1. `ingestion/csv_parser.py::_infer_outcome` может определить Sustained по наличию кадров
   или начального потока. Классификатор на таких метках может выучить правило парсера,
   а не физический исход. Нужна проверенная разметка по отчёту.
2. `parse_air_display` использует минимальное распознанное число как скорость погасания
   при наличии слова extinction. В строке `5 down to ext` число 5 — единственное число;
   численного конечного порога в этой строке нет. `<1` также превращается в 0,5.
   Для ML исходные интервалы/неизвестные значения должны сохраняться без фиктивной точности.
3. `parse_fuel_sample_material` использует PMMA как значение по умолчанию для незнакомого
   текста. Для расширения каталога это неприемлемо: неизвестный материал должен оставаться
   неизвестным до сопоставления с подтверждённым описанием.
4. У B2, P22a, P22b, T28a, T28b отмечены аномалии конечного O₂. При этом импорт CO
   всегда устанавливает `verified`, независимо от статуса условий. Доверять одному этому флагу нельзя.
5. В 13 исходных строках начальный CO отрицателен; нормализатор обнуляет его как дрейф
   датчика. Состояние датчика и изменение значения нужно учитывать в ML provenance.
6. Одинаковые сохранённые начальные признаки не гарантируют одинаковую цель: для двух
   PMMA-стержней Concurrent при 18% O₂ и 5 см/с конечный CO составляет 22 и 116 ppm.
   Возможны разные начальные CO, длительность, история горения и другие пропущенные факторы;
   это не автоматическое доказательство ошибочности измерений.
7. FAQ сообщает о медленном отклике датчика потока и о включении послепрожиговых снимков
   в число кадров. Конечные концентрации зависят от протокола; это не универсальные
   характеристики материала, выводимые только из O₂ и начального потока.

## 7. Вывод и следующий шаг

Не обучать и не объявлять готовую нейросеть или универсальный combustion simulator.
Сначала подготовить task-specific eligibility/review contract и воспроизводимый pipeline,
который умеет завершаться с `INSUFFICIENT_DATA`, оставляя текущую одобренную модель неизменной.

Первая экспериментальная задача — отдельная, узкая регрессия CO/CO₂ в согласованном
протоколе после проверки исходных условий и времени измерения. Приоритетная будущая
задача flame spread требует реальных измеренных скоростей, которых сейчас в CSV нет.
Состояние `OBSERVED` доступно для подтверждённых исходных измерений без обучения.

Для 35% O₂, другого давления, неизвестного материала и частичной гравитации текущие
данные не дают оснований для интерполяции. Добавление 13 исследований само по себе
не исправляет это: нужны сопоставимые измерения в конкретных целевых областях.
